# Ch3. 실무 기준 설계형

단순 알고리즘이 아니라 **요구사항을 객체로 모델링하고 정책을 분리**하는 설계형 문제.
실무 면접·과제 전형에서 나오는 유형. "어떤 책임을 어디로 분리했고, 요구가 바뀌면 어디만 고치면
되는가"를 설명할 수 있어야 한다.

## 문제 목록

| # | 문제 | 빈출도 | 설계 포인트 |
|---|------|:------:|-------------|
| 01 | CurrencyExchange | ★★★ | 수수료·프로모션 정책을 전략으로 분리 |
| 02 | ParkingLot | ★★★★ | 요금 정책, 자리 배정 |
| 03 | ContractManager | ★★★ | 상태(enum) 전이 규칙 |
| 04 | ProfitSharing | ★★★ | 정산 규칙, 반올림 처리 |
| 05 | MeetingRoomBooking | ★★★★ | 여러 방 구간 예약, 겹침 판정 (빌드블록 실제 출제) |

## 핵심 학습 포인트

- **정책 분리**: 변하는 규칙(수수료/요금/정산률)을 인터페이스+구현으로 떼어내, 새 정책이 생겨도
  기존 코드를 안 건드리게(OCP) 만든다.
- **상태 모델링**: enum + 허용된 전이만 통과시키는 규칙으로 잘못된 상태 변경을 막는다.
- **구간 다루기**: 05번은 반열린 구간 `[start, end)` 겹침 판정 `s1 < e2 && s2 < e1` 이 핵심.
  → `appendix/cheatsheets/interval-overlap.md` 와 함께 보면 좋다.

## 풀이 순서 추천

1. **05_MeetingRoomBooking** — 가장 자기완결적이고 구간 겹침 한 개념. 여기부터.
2. **02_ParkingLot** → **01_CurrencyExchange**: 정책 분리 감 잡기.
3. **03_ContractManager** → **04_ProfitSharing**: 상태/정산 규칙 모델링.

> 푼 뒤에는 "요구사항이 이렇게 바뀌면 어느 클래스를 고치는가?"를 스스로 질문해보자.
