# 수익 분배 (실무 설계형) — 해설

> 막히기 전에 골격(`ProfitSharing.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
투자자별 지분율(%)을 등록하고, 총 수익을 지분율대로 분배한다. 금액은 정수라 나누어떨어지지
않을 수 있는데, 그때 남는 1원 단위를 지분이 큰 투자자부터 채워 **합이 정확히 총액**이 되게 한다.

## 핵심 직관 (1줄)
1차로 `floor(amount * rate / 100)` 씩 분배하면 항상 약간 모자라니, **남은 잔액을 지분 내림차순으로
1원씩** 나눠 총합을 맞춘다.

## 자료구조
- `Map<String,Integer> map` : 이름 → 지분율.
- `Map<String,Integer> profitMap` : 이름 → 분배액(결과).
- `int sum` : 누적 지분 합 (등록 시점 검증용).

## 알고리즘
1. `register` : 중복 이름 / 0~100 범위 / 누적 100 초과를 차례로 검증 후 등록, `sum += percent`.
2. `distribute(amount)` :
   - `sum < 100` 이면 예외 (지분이 다 안 찼는데 분배 금지).
   - 각자에게 `floor(amount * rate / 100)` 배정, 남은 잔액 누적.
   - 잔액 > 0 이면 지분 내림차순 정렬 후 1원씩 라운드로빈으로 소진.

## 불변식
분배가 끝나면 `profitMap` 값의 합 == 입력 `amount`. (잔액 분배가 이를 보장)

## 복잡도
- `register` : O(1)
- `distribute` : O(N log N) (잔액 분배용 정렬). 잔액은 최대 N-1 원이라 라운드로빈도 O(N).

## 함정 ⚠️
- **정수 나눗셈 손실**: floor 만 하면 합이 총액보다 작다. 반드시 잔액을 재분배.
- **누적 지분 검증은 등록 시점**: 등록할 때 100 초과를 막아야 분배가 단순해진다.
- **지분 합 100 미만 분배 금지**: 누락 지분이 있으면 분배 기준이 불완전 → 예외.
- **재사용 시 상태 초기화**: `profitMap`/`sum` 이 인스턴스 필드라, 한 번 쓴 뒤 `clear()` 안 하면
  다음 분배가 이전 결과에 오염된다. (테스트에서 매번 `clear()` 호출)
- **잔액 분배 기준의 공정성**: "지분 큰 순"은 하나의 정책일 뿐. 면접에선 기준을 명시하고 합의해야 한다.

## 대안 / 최적화
- 비율을 `BigDecimal`/유리수로 다루면 floor 오차를 더 정밀하게 통제 가능.
- "최대 잔여(largest remainder)" 방식: floor 후 나머지(`amount*rate % 100`)가 큰 순으로 1원씩 →
  지분 크기보다 공정하다고 보는 표준 배분법(헤어 방식). 정책 선택지로 언급하면 가산점.

## 면접 답변 (한국어 1분)
> "지분율대로 정수 금액을 나누는 문제인데, floor 로만 나누면 합이 총액보다 모자랍니다. 그래서 1차로
> 각자 floor(amount*rate/100)를 주고, 남은 잔액을 지분 큰 순서로 1원씩 채워 합이 정확히 총액이 되게
> 했습니다. 등록 단계에서 중복·범위·누적 100 초과를 검증해서 분배 단계는 깔끔하게 유지했고, 지분 합이
> 100 미만이면 분배를 막았습니다. 잔액 분배 기준은 정책이라, 실무라면 '지분 순'인지 '최대 잔여'인지
> 합의가 필요하다고 말씀드릴 것 같습니다."

## 설계 포인트
- **등록(검증) ↔ 분배(계산) 분리**: 지분 유효성은 register 가, 금액 계산은 distribute 가 책임.
  → 검증 규칙이 바뀌어도 분배 로직은 그대로.
- **확장 시 건드릴 곳**: 잔액 분배 정책 변경 → distribute 의 정렬 기준(또는 정책 객체로 추출).
  지분 검증 규칙 변경 → register.

## Follow-up
- **잔액 분배를 '최대 잔여'로?** 정렬 키를 `(amount*rate)%100` 내림차순으로 교체.
- **소수 지분(40.5%)?** percent 를 정수가 아닌 비율로 받고 BigDecimal 로 계산.
- **여러 번 분배 누적?** profitMap 을 누적할지 매번 초기화할지 정책 결정(현재는 clear 로 초기화 전제).
