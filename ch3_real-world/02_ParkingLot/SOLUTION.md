# 주차장 정산 시스템 (실무 설계형) — 해설

> 막히기 전에 골격(`ParkingLot.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
차량 입·출차를 기록하고, 출차 시 주차 시간(분)을 반환하며, 분으로 요금을 계산한다.
시간은 `"HH:MM"` 문자열이며 같은 날 안에서만 다룬다.

## 핵심 직관 (1줄)
"지금 주차 중인 차"만 `Map<차번호, 입차시각>` 으로 추적하면, 입차=put, 출차=remove + 시간차 계산.

## 자료구조
- `Map<String, LocalTime> parkingMap` : 차번호 → 입차 시각. 주차 중인 차만 들어있다.
- `Fee` : 요금 계산 전용 정책 객체.

## 알고리즘
1. `enter` : 이미 키가 있으면 중복 입차 예외, 없으면 `LocalTime.parse(time)` 저장.
2. `exit` : 키 없으면 예외. `Duration.between(입차, 출차).toMinutes()` 로 분 계산 후 `remove`.
3. `calculateFee` : 30분까지 기본 1000, 초과분을 10분 단위 올림(`Math.ceilDiv`)해 500원씩, 상한 15000.

## 불변식
`parkingMap` 에 있는 차 == 현재 주차 중. 출차하면 즉시 빠지므로 같은 차의 다음 입차가 가능.

## 복잡도
- `enter`/`exit` : O(1) (HashMap)
- `calculateFee` : O(1)

## 함정 ⚠️
- **없는 차 출차 / 중복 입차**: 둘 다 `IllegalStateException` 으로 방어. 안 하면 NPE 나 데이터 오염.
- **30분 경계**: `<= 30` 은 기본요금만. 31분이면 초과 1분 → `ceilDiv(1,10)=1` → 한 칸(500) 부과.
- **요금 상한**: `Math.min(fee, 15000)` 으로 캡. 안 하면 종일 주차가 비현실적 금액.
- **`Math.ceilDiv`**: 초과분을 10분 단위로 "올림"해야 한다. 일반 나눗셈은 9분을 0칸으로 깎음.

## 대안 / 최적화
- `"HH:MM"` 을 직접 `parseInt(...)*60 + parseInt(...)` 로 분 변환해도 된다(LocalTime 의존 제거).
- 자정 넘김(over-midnight)을 허용하려면 날짜를 함께 저장하거나 분이 음수면 +1440 보정.

## 면접 답변 (한국어 1분)
> "핵심 질문은 '지금 어떤 차가 주차 중인가'를 어떻게 추적하느냐였습니다. 그래서 차번호를 키,
> 입차 시각을 값으로 하는 HashMap 을 썼습니다. 입차는 put, 출차는 시간차를 분으로 계산하고 remove
> 합니다. 이미 있는 차가 또 입차하거나 없는 차가 출차하면 예외로 막았습니다. 요금 규칙은 자주
> 바뀔 수 있어서 Fee 라는 별도 객체로 분리했습니다. 30분 경계와 요금 상한을 코너 케이스로 잡았습니다."

## 설계 포인트
- **주차 추적 ↔ 요금 정책 분리**: `ParkingLot` 은 입·출차 상태만, `Fee` 는 요금표만.
  → 요금 정책이 바뀌어도(예: 평일/주말 차등) `enter/exit` 는 안 건드린다. `Fee` 만 교체/확장.
- **확장 시 건드릴 곳**: 새 요금제 → `Fee` 를 인터페이스로 추상화하고 구현 추가. 시간 표현 변경 → `tLocalTime` 만.

## Follow-up
- **여러 요금제(VIP/일반)?** `Fee` 를 인터페이스로 빼고 차종별 전략 주입.
- **자정 넘김?** 입차에 날짜를 함께 저장하거나, 음수 분이면 1440 더해 보정.
- **동시성?** 멀티스레드면 `ConcurrentHashMap` + 차번호 단위 락 고려.
