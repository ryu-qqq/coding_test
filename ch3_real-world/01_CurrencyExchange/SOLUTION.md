# 환율 변환기 (실무 설계형) — 해설

> 막히기 전에 골격(`CurrencyExchange.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
`"USD:KRW:1390.50,USD:JPY:155.20,..."` 형식 문자열을 파싱해 통화를 변환한다.
직접 환율이 없으면 다른 통화를 경유(예: USD→KRW→EUR)해서라도 변환하고, 어떤 경로로도
도달 불가능하면 예외를 던진다.

## 핵심 직관 (1줄)
통화 = 노드, 환율 = 가중 간선인 **양방향 그래프**로 보고, 시작 통화에서 **BFS** 로 퍼지며
누적 환율을 들고 다닌다.

## 자료구조
- `Map<String, Set<Node>> rateMap` : 인접리스트. 통화 → (이웃 통화, 환율) 집합.
- `Node(country, rate)` : BFS 큐에 담는 단위. 여기서 `rate` 는 "**시작점에서 이 통화까지의 누적 환율**".

## 알고리즘
1. 초기화: 각 `from:to:rate` 항목마다 정방향 `from→to(rate)` **와 역방향 `to→from(1/rate)`** 를
   둘 다 등록한다. (한 줄만으론 GBP:USD 의 USD→GBP 같은 역방향이 안 생김)
2. `convert(from,to,amount)`:
   - `from == to` 면 `amount` 그대로 반환.
   - `Node(from, 1.0)` 를 큐에 넣고 BFS. 각 이웃에 대해
     - 타겟이면 `cur.rate * edge.rate * amount` 반환 (누적 × 마지막 간선).
     - 아니면 누적 환율 `cur.rate * edge.rate` 를 들려 큐에 추가.
   - 큐가 비면 경로 없음 → 예외.

## 불변식
큐에서 꺼낸 `Node` 의 `rate` 는 항상 "시작 통화 → 그 통화"의 누적 곱이다.
그래서 타겟 도달 시 마지막 간선 한 번만 더 곱하면 끝.

## 복잡도
- 초기화: O(E) (E = 항목 수의 2배, 정/역방향)
- convert: O(V + E)

## 함정 ⚠️
- **역방향 누락**: 정방향만 넣으면 KRW→USD, USD→GBP 같은 경로가 끊긴다. 초기화에서 `1/rate` 도 등록.
- **누적 환율 누락**: 타겟 도달 시 `edge.rate` 만 곱하면 다단계에서 틀린다. `cur.rate` 까지 곱해야 함.
  (1단계 경로에선 `cur` 이 시작노드라 rate=1.0 → 우연히 맞아서 안 들킨다.)
- **방문 체크 타입**: `visited` 는 `Set<String>` 이므로 `Node` 가 아니라 `n.getCountry()` 로 검사.
- **visited/큐는 지역변수**: convert 호출마다 새로 만들어야 한다. 인스턴스 필드로 두면 다음 호출이 오염됨.
- **경로 없음은 0.0 이 아니라 예외**: 0.0 은 "0원"이라는 정상 결과와 구분이 안 된다.

## 대안 / 최적화
- 환율은 곱셈이라 누적 정밀도 손실(double) 우려 → 대규모면 `BigDecimal` 고려.
- "최소 경유" 같은 추가 요구가 없으면 BFS/DFS 무관. 가중치 부호가 일정하므로 다익스트라 불필요.

## 면접 답변 (한국어 1분)
> "통화를 노드, 환율을 간선으로 보는 그래프 문제로 모델링했습니다. 직접 환율이 없어도 경유 변환을
> 해야 해서, 초기화 때 정방향과 역방향(1/rate)을 둘 다 인접리스트에 넣어 양방향 그래프를 만들었습니다.
> convert 는 시작 통화에서 BFS 로 퍼지면서 각 노드에 '시작점부터의 누적 환율'을 들려 보냅니다.
> 타겟에 도달하면 누적 환율에 마지막 간선만 곱해서 반환하고, 큐가 비면 경로가 없는 것이니 예외를
> 던집니다. 수수료 같은 부가 정책은 FeePolicy 인터페이스로 분리해서 변환 로직과 독립시켰습니다."

## 설계 포인트
- **변환 책임 ↔ 수수료 책임 분리**: `convert` 는 순수 환율 변환만. 수수료는 `FeePolicy`(전략).
  → 프로모션/등급별 수수료가 추가돼도 `convert` 는 그대로, `FeePolicy` 구현만 추가한다.
- **확장 시 건드릴 곳**: 새 수수료 규칙 → `FeePolicy` 새 구현 클래스. 환율 소스 변경 → 생성자 파싱만.

## Follow-up
- **환율이 자주 갱신되면?** rateMap 을 갱신하는 update 메서드 분리, 또는 불변 스냅샷 교체.
- **경로가 여러 개면 어떤 걸?** BFS 라 "최소 경유 수" 경로를 먼저 찾음. "최저 수수료 경로"가 필요하면
  가중치를 비용으로 두고 다익스트라.
