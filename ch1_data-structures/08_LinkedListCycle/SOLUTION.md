# LinkedListCycle (LC 141) — 해설

> 막히기 전에 골격(`LinkedListCycle.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
연결 리스트에 사이클이 있는지 판별한다.

## 핵심 직관 (1줄)
토끼와 거북이(Floyd) — 사이클이 있으면 fast가 slow를 모듈러 거리로 따라잡는다.

## 자료구조
포인터 2개(slow, fast). 추가 메모리 없음.

## 알고리즘
1. `slow = head`, `fast = head`.
2. while `fast != null && fast.next != null`: slow를 1칸, fast를 2칸 전진. 같으면 사이클 발견(true).
3. 루프를 빠져나오면 사이클 없음(false).

## 불변식
사이클이 있으면 매 스텝마다 fast-slow 거리가 사이클 길이 모듈러로 1씩 줄어든다 → 반드시 만난다.

## 복잡도
시간 O(N), 공간 O(1).

## 함정 ⚠️
- `fast.next.next` NPE 방지: while 조건에서 `fast != null && fast.next != null` 둘 다 체크.
- HashSet으로 방문 노드를 추적해도 풀리지만 공간이 O(N)이라 Floyd보다 열등하다.

## 대안 / 최적화
사이클 시작점까지 찾아야 하면(LC 142) 만난 후 한 포인터를 head로 옮겨 둘 다 1칸씩 가다 만나는 점이 시작점.

## 면접 답변 (한국어 1분)
> "Floyd의 토끼와 거북이 알고리즘으로 풀었습니다. slow 포인터는 한 칸씩, fast 포인터는 두 칸씩 전진합니다. 사이클이 없으면 fast가 먼저 null에 도달해서 루프를 빠져나가고 false 반환합니다. 사이클이 있다면 fast와 slow의 모듈러 거리가 매 스텝마다 1씩 줄어들기 때문에 반드시 만나게 됩니다. NPE 방지를 위해 while 조건에서 fast와 fast.next 둘 다 null 체크를 해줍니다. 공간 O(1)로 풀 수 있는 게 핵심 장점이고, HashSet으로 방문 노드를 추적해도 풀리지만 공간이 O(N)이라 비효율입니다."

## Follow-up
- **왜 fast가 slow를 반드시 만나나?** 사이클에 진입하면 두 포인터가 모두 사이클 안에 있고, fast-slow 거리가 사이클 길이를 모듈러로 매 스텝 1씩 좁혀진다. 사이클 길이만큼 돌면 반드시 같은 노드에 위치한다.
- **사이클 시작점은? (LC 142)** 만난 지점에서 한 포인터를 head로 옮긴 뒤 둘 다 1칸씩 가면 만나는 지점이 시작점이다. head→시작점 거리와 만난점→시작점(진행 방향) 거리가 같다는 사실을 이용한다.
