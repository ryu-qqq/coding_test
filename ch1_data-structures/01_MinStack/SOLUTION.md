# MinStack (LC 155) — 해설

> 막히기 전에 골격(`MinStack.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
모든 연산이 O(1)인 스택. 단, `getMin()`(현재 스택의 최솟값)도 O(1)이어야 한다.

## 핵심 직관 (1줄)
보조 스택(`minStack`)의 top이 항상 **현재 살아있는 원소들의 최솟값**이도록 유지한다.

## 자료구조
- `mainStack` : 일반 데이터 스택
- `minStack` : 최솟값 추적용 보조 스택

## 알고리즘
1. `push(v)` : 메인에 무조건 넣고, `minStack`이 비었거나 `v <= minStack.peek()`이면 `minStack`에도 push.
2. `pop()` : 메인에서 꺼내고, 꺼낸 값이 `minStack.peek()`와 같으면 `minStack`도 pop.
3. `getMin()` : `minStack.peek()` 반환.

## 불변식
`minStack.top()`은 항상 `mainStack`에 살아있는 모든 원소의 최솟값.

## 복잡도
- 시간: 모든 연산 O(1)
- 공간: O(N) (worst: 단조 감소 입력 시 minStack도 N개)

## 함정 ⚠️
- push 조건은 반드시 `<=`. `<`만 쓰면 **중복 최솟값**에서 pop 시 minStack이 먼저 비어버림.
- 조건 결합은 `||` (isEmpty OR `<=` peek). `&&`면 첫 push 자체가 누락됨.
- pop 비교는 `equals()`. Integer 박싱 캐시(-128~127) 범위 밖에서 `==`는 위험.

## 대안 / 최적화
단일 스택에 `(val, currentMin)` 쌍을 저장해 동일 효과. 또는 차이값 `(val - min)`만 저장해 공간 절약.

## 면접 답변 (한국어 1분)
> "getMin이 O(1)이어야 한다는 게 핵심이라 스택 두 개를 썼습니다. 하나는 데이터 스택, 다른 하나는
> 현재 최솟값을 추적하는 보조 스택입니다. push 때 보조 스택이 비었거나 들어오는 값이 보조 top보다
> 작거나 같으면 보조에도 넣고, pop 때 메인에서 꺼낸 값이 보조 top과 같으면 보조도 pop합니다.
> 그러면 보조 top이 항상 현재 최솟값이라 getMin이 O(1)입니다. 주의점은 push 조건을 `<`가 아니라
> `<=`로 해야 중복 최솟값에서 pop 짝이 맞는다는 것입니다."

## Follow-up
- **왜 `<=`?** 같은 최솟값이 여러 번 push될 때 `<`만 쓰면 보조엔 한 번만 들어가는데 메인에선 여러 번
  pop되어 보조가 먼저 비어버림. `<=`로 중복도 모두 넣어야 짝이 맞음.
- **공간 더 줄이려면?** 단일 스택에 `(val - currentMin)` 차이값만 저장. push 시 음수면 새 최솟값.
