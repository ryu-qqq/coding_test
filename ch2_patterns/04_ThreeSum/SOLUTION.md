# 3Sum (LC 15) — 해설

> 막히기 전에 골격(`ThreeSum.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
정수 배열 `nums`에서 `a + b + c == 0`인 모든 유니크한 삼중쌍을 반환한다.

## 핵심 직관 (1줄)
정렬 후 한 원소를 고정(i)하고 나머지는 양 끝(l, r) 투포인터로 좁힌다.

## 자료구조
- 정렬된 배열 + 투포인터.

## 알고리즘
1. 정렬.
2. `for i in 0..n-3`: `nums[i] > 0`이면 break. `i > 0 && nums[i] == nums[i-1]`이면 continue (중복 i 스킵).
3. `l = i+1`, `r = n-1`. `sum = nums[i] + nums[l] + nums[r]`.
4. `sum < 0` → `l++`. `sum > 0` → `r--`. `sum == 0` → 결과 추가, l/r 중복 스킵, `l++`/`r--`.

## 불변식
결과 리스트에 동일 삼중쌍은 한 번만 들어간다.

## 복잡도
- 시간: O(N²)
- 공간: O(1) (정렬 비용 별도, 결과 제외)

## 함정 ⚠️
- 중복 제거를 i, l, r **세 군데 모두**에서 해야 한다.
- 정렬을 안 하면 투포인터 전략 자체가 성립하지 않는다.
- `nums[i] > 0`이면 정렬돼 있으니 그 뒤 합이 0이 될 수 없어 break.

## 대안 / 최적화
HashMap 풀이도 가능하나 중복 처리가 더 까다롭다. 정렬+투포인터가 더 깔끔하다.

## 면접 답변 (한국어 1분)
> "정렬 후 투포인터 풀이입니다. 정렬하면 한 원소 i를 고정하고 나머지 두 원소를 양 끝에서 좁히는
> 투포인터를 적용할 수 있습니다. 합이 0보다 작으면 l을 늘리고, 크면 r을 줄이고, 0이면 결과에
> 추가합니다. 중복 제거가 핵심인데 i, l, r 세 군데 모두에서 같은 값이 연속되면 스킵해야 합니다.
> nums[i]가 0보다 크면 그 뒤로 합이 0이 될 수 없으니 break합니다. 시간 O(N²), 공간은 결과 제외
> O(1)입니다."

## Follow-up
- **중복 제거 안 하면?** `[-1, -1, 2]` 같은 답이 여러 번 나올 수 있다. i, l, r 셋 다 같은 값 연속을
  스킵해야 유일성이 보장된다.
- **왜 `nums[i] > 0`이면 break?** 정렬돼 있어 i 뒤 모든 원소가 `nums[i]` 이상이고, 셋 다 양수면 합이
  0이 될 수 없다.
