# ClimbingStairs (LC 70) — 해설

> 막히기 전에 골격(`ClimbingStairs.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
한 번에 1 또는 2 계단을 오를 수 있을 때, n번째 계단까지 가는 방법의 수.

## 핵심 직관 (1줄)
본질이 피보나치 — n칸에 도달하려면 (n-1)칸이나 (n-2)칸에서 와야 하므로 `f(n) = f(n-1) + f(n-2)`.

## 자료구조
변수 두 개(rolling DP). dp 배열은 불필요.

## 알고리즘
- `n <= 2`면 `n` 반환. `prev2=1, prev1=2`.
- `for i in 3..n`: `cur = prev1 + prev2; prev2 = prev1; prev1 = cur`.
- `prev1` 반환.

## 불변식
매 반복 직전 `prev2 = f(i-2)`, `prev1 = f(i-1)`.

## 복잡도
- 시간: O(N)
- 공간: O(1)

## 함정 ⚠️
- base case `n=1 → 1`, `n=2 → 2` 분기.
- n이 매우 크면 int 오버플로우(LC는 n ≤ 45 정도라 안전).

## 대안 / 최적화
- 행렬 거듭제곱으로 O(log N).
- Binet 공식으로 O(1)(부동소수점 정확도 이슈로 큰 n에서는 부정확).

## 면접 답변 (한국어 1분)
> "본질이 피보나치 수열입니다. n번째 계단에 도달하려면 직전 칸(n-1)이나 두 칸 전(n-2)에서 와야 하니까
> f(n) = f(n-1) + f(n-2)입니다. dp 배열 없이 직전 두 값만 굴리는 rolling 두 변수로 O(N) 시간, O(1) 공간에
> 풀립니다. base case는 n=1이면 1, n=2이면 2입니다. 더 빠르게 하려면 행렬 거듭제곱으로 O(log N)도 되고
> Binet 공식으로 O(1)도 있는데 부동소수점 오차 때문에 큰 n에서는 부정확합니다."

## Follow-up
- **왜 dp 배열을 안 쓰나?** 매 단계에서 직전 두 값만 필요하므로 변수 두 개로 충분. 공간을 O(N)→O(1)로 줄인다.
- **1, 2 외에 1, 2, 3 계단도 가능하면?** `f(n) = f(n-1) + f(n-2) + f(n-3)`으로 확장, 변수 세 개 rolling으로 푼다.
