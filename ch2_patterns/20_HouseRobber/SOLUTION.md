# HouseRobber (LC 198) — 해설

> 막히기 전에 골격(`HouseRobber.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
`nums[i]`는 i번째 집의 금액. 인접한 두 집은 동시에 털 수 없을 때 얻을 수 있는 최대 금액.

## 핵심 직관 (1줄)
각 집에서 "현재 집을 털기(`prev2 + nums[i]`) vs 안 털기(`prev1`)" 중 큰 값을 취한다.

## 자료구조
변수 두 개(rolling DP).

## 알고리즘
- 길이 0이면 0, 길이 1이면 `nums[0]`.
- `prev2 = nums[0]`, `prev1 = max(nums[0], nums[1])`.
- `for i in 2..n-1`: `cur = max(prev1, prev2 + nums[i]); prev2 = prev1; prev1 = cur`.
- `prev1` 반환.

(동등 변형: `prev2=prev1=0`에서 시작해 `for v in nums`로 돌리면 base case 분기가 사라진다.)

## 불변식
매 반복 직후 `prev1` = "0..i까지의 최대 수익", `prev2` = "0..i-1까지의 최대 수익".

## 복잡도
- 시간: O(N)
- 공간: O(1)

## 함정 ⚠️
- 빈 배열은 0, 길이 1은 `nums[0]` — base case를 빠뜨리지 말 것(0/0 시작 변형을 쓰면 자연 처리됨).
- ClimbingStairs와 점화식 모양이 비슷하지만 **합이 아니라 max**를 취한다.

## 대안 / 최적화
dp[] 배열 풀이도 동일 복잡도이나 공간 O(N). rolling 두 변수가 더 낫다.

## 면접 답변 (한국어 1분)
> "각 집에서 두 가지 선택이 있습니다. 현재 집을 털고 두 칸 전까지의 최대 수익에 더하거나, 안 털고 직전 최대
> 수익을 유지하거나. 둘 중 max가 새로운 prev1이 됩니다. 직전 두 값만 필요하니 변수 두 개로 굴리면 O(N) 시간,
> O(1) 공간입니다. 빈 배열은 0, 길이 1은 그 값 자체로 처리합니다. ClimbingStairs와 점화식이 비슷하지만 합이
> 아니라 max를 취하는 점이 다릅니다."

## Follow-up
- **원형 배열이라면(LC 213)?** 첫 집과 마지막 집이 인접하니 둘 중 하나는 못 턴다. (0..n-2)와 (1..n-1) 두 범위로 나눠 각각 House Robber I을 적용하고 max를 취한다.
- **트리 구조라면(LC 337)?** 트리 DP — 각 노드에서 (털기, 안 털기) 두 값을 반환하는 후위 순회로 푼다.
