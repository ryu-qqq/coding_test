# JadenCase 문자열 만들기 (Programmers 12951) — 해설

> 막히기 전에 골격(`JadenCase.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
모든 단어의 첫 글자는 대문자, 나머지는 소문자로 변환한다. 단어는 공백 1개로 구분되며, 연속 공백이나 양끝 공백은 **그대로 보존**되어야 한다.

## 핵심 직관 (1줄)
`split(" ", -1)` 로 공백 구조를 잃지 않고 쪼갠 뒤, 각 단어를 "첫 글자 대문자 + 나머지 소문자"로 바꿔 다시 공백으로 잇는다.

## 자료구조
- 문자열 배열(split 결과) + `StringBuilder` (또는 `String.join`).

## 알고리즘
1. `s.split(" ", -1)` → 빈 토큰까지 보존된 배열.
2. 각 단어가 비어있지 않으면 `toUpperCase(첫글자) + substring(1).toLowerCase()`.
3. 단어들을 공백 1개로 다시 합친다.

## 불변식
변환 후에도 토큰 개수와 위치가 보존되므로, 공백으로 join 하면 원래의 공백 구조가 복원된다.

## 복잡도
- 시간: O(N) (N = 문자열 길이). 공간: O(N).

## 함정 ⚠️ (String API 집중)
- **`split(" ", -1)` 의 `-1`**: 핵심 함정. 인자 없는 `split(" ")` 은 **끝쪽 빈 문자열을 버린다**. 그래서 `"  hello   world  "` 의 끝 공백이 사라진다. limit 을 음수(-1)로 주면 끝 빈 토큰까지 모두 유지되어 공백 보존이 된다.
  - `"a  b".split(" ")` → `["a", "", "b"]` (중간 빈 토큰은 유지) 지만, `"a b  ".split(" ")` → `["a","b"]` (끝 빈 토큰 제거). `-1` 이면 `["a","b","",""]`.
- **빈 단어 가드**: 연속 공백 → 빈 토큰 `""`. `charAt(0)` 전에 `!word.isEmpty()` 로 보호하지 않으면 StringIndexOutOfBounds.
- **첫 글자 무조건 대문자화**: 정의가 "첫 글자 대문자 + 나머지 소문자"이므로 원래 글자가 무엇이든 적용. `Character.toUpperCase('3')` 은 `'3'` 을 그대로 반환하므로 숫자 분기는 불필요. `isLowerCase` 같은 조건을 붙이면 `"FOR"`→`"FOR"`(오답, 정답 `"For"`) 처럼 대문자 시작 단어가 안 다듬어진다.
- **나머지 소문자화 누락 주의**: `substring(1).toLowerCase()` 를 빼면 `"unFollowed"`→`"UnFollowed"` 가 되어 오답.
- **join 시 trailing space**: 모든 단어 뒤에 공백을 붙이면 마지막에 공백이 하나 더 남는다. 끝 공백 1개를 잘라내거나(이 정답은 `substring(0, len-1)`) 처음부터 `String.join(" ", arr)` 로 사이에만 끼우는 게 안전.

## 대안 / 최적화
- `String.join(" ", 변환된배열)` 이 가장 깔끔(trailing space 문제가 원천 차단). 단어 변환을 별도 메서드로 분리하면 가독성 ↑.

## 면접 답변 (한국어 1분)
> "공백 보존이 핵심 함정이라 split(\" \", -1) 을 썼습니다. 인자 없는 split 은 끝쪽 빈 토큰을 버려서 양끝 공백이 사라지는데, limit 을 -1 로 주면 빈 토큰까지 유지돼 공백 구조가 보존됩니다. 각 단어는 비어있지 않을 때만 첫 글자를 toUpperCase, 나머지를 substring(1).toLowerCase 로 바꿨습니다. 첫 글자는 원래가 숫자든 소문자든 무조건 대문자화 규칙이라 분기가 필요 없고, toUpperCase('3')='3' 이라 숫자도 안전합니다. 다시 합칠 땐 trailing space 가 안 생기게 String.join 을 쓰는 게 깔끔합니다. 전체 O(N) 입니다."

## Follow-up
- **`split(" ")` 과 `split(" ", -1)` 차이?** limit 음수면 끝쪽 빈 문자열을 제거하지 않는다. 기본(0)은 끝 빈 토큰을 버린다.
- **정규식 공백 `\\s+` 로 split 하면?** 연속 공백 정보를 잃어 이 문제엔 부적합. 공백 개수까지 보존해야 하므로 리터럴 `" "` + limit -1.
