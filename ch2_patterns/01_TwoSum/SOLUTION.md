# Two Sum (LC 1) — 해설

> 막히기 전에 골격(`TwoSum.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
`nums` 배열에서 합이 `target`이 되는 두 인덱스 쌍을 찾아 반환한다. 정확히 한 쌍의 답이 존재한다고 가정.

## 핵심 직관 (1줄)
보수(`target - nums[i]`)가 이미 본 적 있는지 한 패스로 확인한다.

## 자료구조
- `HashMap<Integer, Integer>` : 값 → 인덱스.

## 알고리즘
1. `map = {}`.
2. `for i in 0..n-1`: `comp = target - nums[i]`. `map`에 `comp`가 있으면 `[map.get(comp), i]` 반환. 없으면 `map.put(nums[i], i)`.

## 불변식
`map`은 "현재 i 직전까지의 (값 → 인덱스)" 매핑을 정확히 반영한다.

## 복잡도
- 시간: O(N) (한 패스)
- 공간: O(N) (map)

## 함정 ⚠️
- lookup을 먼저 하고 put을 나중에 해야 자기 자신을 두 번 사용하지 않는다.
- `[3, 3]` target 6 같은 중복값 케이스도 위 순서로 자연 처리된다.

## 대안 / 최적화
정렬 + 투포인터로 O(N log N) 시간 + O(1) 공간. 단, 인덱스 반환이면 원본 인덱스를 같이 추적해야 한다.

## 면접 답변 (한국어 1분)
> "HashMap을 이용한 one-pass 풀이입니다. 핵심 아이디어는 각 인덱스마다 보수, 즉 target에서 현재 값을
> 뺀 값이 이미 본 적 있는지 확인하는 겁니다. 보수가 map에 있으면 그 인덱스와 현재 인덱스를 반환하고,
> 없으면 현재 값을 인덱스와 함께 map에 저장합니다. 순서가 중요한데, lookup을 먼저 하고 put을 나중에
> 해야 자기 자신을 두 번 사용하는 실수가 안 생깁니다. 시간 O(N), 공간 O(N)입니다."

## Follow-up
- **왜 lookup을 먼저 하고 put을 나중에?** 같은 인덱스 i를 두 번 쓰지 않기 위해서다. put 먼저 하면
  `nums[i]`가 자기 보수일 때 자기 자신을 매칭할 수 있다.
- **공간을 O(1)으로 줄이려면?** 정렬 후 투포인터를 쓰면 가능하지만 정렬이 O(N log N)이고, 인덱스
  반환이 요구사항이면 원본 인덱스를 같이 끌고 가야 해서 추가 작업이 필요하다.
