# Group Anagrams (LC 49) — 해설

> 막히기 전에 골격(`GroupAnagrams.java`)부터 직접 채워보고, 그래도 안 풀리면 이 문서를 펼쳐보세요.

## 문제
문자열 배열을 받아 서로 애너그램끼리 그룹핑한다.

## 핵심 직관 (1줄)
문자열을 정렬한 결과(또는 a-z 카운트 26개를 직렬화한 값)를 키로 삼아 같은 키끼리 묶는다.

## 자료구조
- `HashMap<String, List<String>>`.

## 알고리즘
1. `map = {}`.
2. `for s in strs`: `key = sorted(s.toCharArray())`. `map.computeIfAbsent(key, k -> new ArrayList<>()).add(s)`.
3. `return map.values()`.

## 불변식
매 반복 후 `map[key]`의 모든 문자열은 서로 애너그램이다.

## 복잡도
- 정렬 키 방식: O(N·K log K)
- 카운트 키 방식: O(N·K)
- 공간: O(N·K) (K = 평균 문자열 길이)

## 함정 ⚠️
- 빈 문자열도 그 자체로 그룹 1개.
- 그룹 순서/내부 순서는 LC에서 임의로 허용된다.

## 대안 / 최적화
소문자만 가정하면 길이 26 카운트 배열을 `"#1#0#..."` 형태로 직렬화해 O(K) 키 생성이 가능하다
(정렬 O(K log K)보다 빠름).

## 면접 답변 (한국어 1분)
> "HashMap으로 애너그램을 그룹핑합니다. 핵심은 같은 애너그램이면 정렬했을 때 같은 문자열이 된다는
> 점입니다. 그래서 각 문자열을 정렬한 결과를 키로 쓰고, computeIfAbsent로 같은 키의 리스트에 원본을
> 추가합니다. 마지막에 map의 values를 반환하면 됩니다. 정렬 키 방식은 O(N·K log K)인데, 소문자만
> 가정하면 길이 26 카운트 배열을 직렬화해 O(N·K)로 줄일 수 있습니다."

## Follow-up
- **카운트 키로 더 빠르게?** 각 문자열의 a-z 빈도 26칸 배열을 `#`로 구분해 직렬화하면 정렬 없이 O(K)에
  키를 만들 수 있다.
- **유니코드라면?** 정렬 키 방식이 더 안전하다. 카운트 배열은 알파벳 범위를 가정한다.
