# 코딩테스트 커리큘럼 (Java)

이직/면접용 코딩테스트를 **순서대로 직접 풀어보는** 학습 레포.
자료구조를 손으로 만드는 것부터, 대표 알고리즘 유형, 실무 설계형까지 3챕터로 구성했다.

## 학습 흐름

```
Ch1. 순수 자료구조 직접 구현   →   Ch2. 대표 유형   →   Ch3. 실무 기준 설계형
   (스택·큐·힙·트리·캐시)          (해시·트리·그래프·DP·문자열)   (정책 분리·OOP)
```

권장 순서는 Ch1 → Ch2 → Ch3. 각 챕터 폴더의 `README.md`에 문제 목록·빈출도·풀이 순서가 있다.

## 환경

- **Java 21** 단일 파일 실행 모드(JEP 458) — Gradle/Maven 불필요, 외부 의존성 없음.
- 어서션(`-ea`)을 켜야 테스트가 동작한다.

## 풀이 방법

각 문제 폴더는 **3개 파일**로 구성된다:

| 파일 | 용도 |
|------|------|
| `<문제명>.java` | **골격** — `// TODO`를 직접 채운다. (학습자가 푸는 파일) |
| `Solution.java` | **정답** 코드 (막판 확인용) |
| `SOLUTION.md` | **해설** — 핵심 아이디어·복잡도·함정·면접 답변 |

1. 골격 파일의 `// TODO`를 채운다.
2. 어서션 켜고 실행해 통과시킨다:
   ```bash
   java -ea ch1_data-structures/01_MinStack/MinStack.java
   ```
   통과하면 `✅ ... All tests passed` 출력. (미구현 상태면 `UnsupportedOperationException: TODO`)
3. 막히면 → `SOLUTION.md`, 정답 대조 → `Solution.java`.

> 풀기 전에 파일 상단 주석의 **인터페이스 → 시간복잡도 목표 → (핵심 아이디어/불변식/함정은 스스로)**
> 순서로 읽고, 자료구조와 불변식부터 말로 정리한 뒤 구현하는 습관을 들이자.

## 디렉토리

```

```

## 면접 포인트

- **불변식(invariant)**: 모든 연산 후에도 유지되는 속성을 먼저 정의한다.
- **복잡도**: 구현 후 목표 시간/공간 복잡도를 만족하는지 검증한다.
- **엣지 케이스**: 빈 상태, 단일 원소, 용량 초과, 중복 키/값, 경계 구간.
- **검증 습관**: "통과한 것 같다"가 아니라 `java -ea`로 실제 통과를 확인하고 넘어간다.
